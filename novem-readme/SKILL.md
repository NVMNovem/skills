# Novem README

Help a reader understand what the project does and how to get started.
This is a starter skill; extend it as Novem's README conventions develop.

## Ground the content in the project

Read the existing README and inspect the source, configuration, and scripts
relevant to setup and usage. Preserve correct existing content and adapt the
update to the requested scope.

Document commands, prerequisites, and features supported by the repository.
Do not invent installation steps, environment variables, or project behavior.
If essential information is missing, ask for it or clearly identify the gap.

## Keep the README practical

Start with the project's name and a short explanation of its purpose. Include
setup and a normal usage example when relevant. Add development, testing, or
configuration sections only where they help someone work with the project.

Use clear headings, short explanations, and fenced code blocks for commands.
Prefer relative links for files within the repository. Keep detailed material
in existing documentation and link to it rather than duplicating it.

Before finishing, check that linked repository files exist and that documented
commands match the project's tooling. State which commands were actually run
in the completion report; do not describe untested steps as verified.
